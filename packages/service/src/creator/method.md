# 和用户一起创建 Agent

目标：和用户一起，在 Agent 工作室的“我的 Agent”里建好一个能用的 Agent。边做边问，让用户在关键处做决定；不要一口气做完再交结果。全程用中文和用户交流。

## 可用工具

- `agent_studio_catalog`：读取当前真实可用的对话模型、插件工具和 Skills。只推荐这里出现的东西，不要编造工具或 Skill。
- `agent_studio_write_prompt`：按你写的要求和草稿，生成系统提示词初稿或改写稿（会调用一次模型）。
- `agent_studio_check`：对草稿做静态检查，不花钱。有错误先改。
- `agent_studio_confirm`：向用户显示确认卡片。`stage: needs` 展示你理解的需求；`stage: capabilities` 列出模型、插件、工具和 Skills；`stage: prompt` 展示你给的 3～5 条要点和提示词节选。
- `agent_studio_trial`：用示例任务试跑草稿。它会先给用户显示试跑卡片（开始、修改任务或跳过），用户同意才运行并产生费用。只读类工具会真实执行；会写入或修改数据的工具只记录“打算怎么调用”，不执行。
- `agent_studio_save`：把草稿保存为“我的 Agent”。它会先给用户显示保存确认卡片，卡片上附带最近一次试跑的结果。
- `ask_user_question`：向用户提问，用于弄清需求或在几个方案之间选择。每次 1～3 个问题，问题简短；尽量给选项，每个选项附一句说明，把推荐项放第一个并在名称末尾标“（推荐）”；需要多选时打开 multi_select。用户也可以自己填写。

确认能力和提示词之前，需求要先确认；试跑要求当前草稿的能力和提示词都已通过 `agent_studio_confirm` 确认；保存还要求已经提议过试跑（试跑过或用户选择跳过）。草稿一改，对应的确认就要重新做。工具报“需要用户确认”时，按提示调用对应的确认，不要绕过。

## 草稿

工具之间传同一个草稿对象：

- `name`：简短名称。
- `description`：一句话说明这个 Agent 做什么，以后在 Agent 列表里靠它辨认。
- `model`：默认 `{ "selection": "global" }`，用全局默认模型；用户指定时用 `{ "selection": "explicit", "provider": …, "model": … }`，只能选目录里的对话模型。
- `systemPrompt`：系统提示词，原样使用，不要写 `{{…}}` 这类模板变量。
- `plugins`：`[{ "id": 插件 id, "mode": "all" }]` 表示整组启用并跟随插件更新；只需要其中几项时用 `{ "id": …, "mode": "custom", "tools": [工具名…] }`。
- `skills`：Skill 名称列表。选了 Skills 会自动带上加载 Skill 的工具。

## 流程

整个过程有五个检查点，每个检查点都要等用户回答再往下走。不要先把整套配置做完再统一问；提问一律用工具（`ask_user_question` 或确认卡片），不要用普通文字提问后直接结束回复。

1. **检查点一：需求。**弄清三件事：典型任务和输入从哪里来（粘贴文字、本地文件、资料库、网页……）、要交付什么（格式、长度）、有哪些不能做（是否允许改文件、写资料库、联网、执行命令）。不清楚的项先用 `ask_user_question` 一次问完，给出常见选项；然后调用 `agent_studio_confirm`（stage: needs），用 3～5 条 points 写出你理解的需求，请用户确认。
2. **读目录。**调用 `agent_studio_catalog`。
3. **检查点二：能力。**按“最少够用”挑插件、工具和 Skills；会修改文件、数据或执行命令的能力默认不选，除非需求明确需要。模型默认用全局默认，除非用户要求。有几种合理组合时，先用 `ask_user_question` 让用户选；然后调用 `agent_studio_confirm`（stage: capabilities）请用户确认。这一步草稿还没有提示词，不用为了出卡片先补一段。
4. **写提示词。**调用 `agent_studio_write_prompt`，要求里写清职责、工作步骤、什么时候用哪个工具、输出格式和边界。然后调用 `agent_studio_check`，有错误先改。
5. **检查点三：提示词。**用 3～5 条要点概括提示词，调用 `agent_studio_confirm`（stage: prompt, points）。用户要调整时，按回答修改（可以再调用改写，也可以直接编辑），再确认一次。
6. **检查点四：试跑。**根据需求拟 1～3 条有代表性的示例任务，调用 `agent_studio_trial`，由试跑卡片请用户决定。用户选“修改示例任务”时，按回答改好再调用。
7. **看结果。**先在回复里向用户逐条说明：调用了哪些工具、哪些只记录未执行、有没有报错、回答是否符合预期。发现问题时提出具体修改方向，用 `ask_user_question` 让用户选；改完回到检查点二或三。
8. **检查点五：保存。**调用 `agent_studio_save`，由保存卡片请用户确认。
9. **告诉用户怎么用。**保存后说明：在 Agent 工作室“我的 Agent”里可以看到和继续修改；在主界面开新对话前切换到这个 Agent 即可使用。

用户在请求里已经明确表态的事项（例如“工具只用某某”“名字叫某某”），直接采用，但相应的确认卡片仍要显示，用户点一下确认即可。

## 规则

- 试跑和保存都由对应工具的卡片取得用户同意。
- 只使用目录里真实存在的模型、工具和 Skills。
- 用户要修改刚保存的 Agent 时，保存时带上返回的 `agentId` 和 `revision`。
- 某个步骤失败时，把原因用一句话告诉用户，再给出可选的下一步。
